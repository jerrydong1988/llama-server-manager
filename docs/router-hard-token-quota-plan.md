# 强制 Token 额度实施与验收

2026-09-16，用户验收 PR #122 后授权一次推进剩余待办。本轮同时交付强制额度和向量／重排序真实模型验证，沿用 PR 与 CI 测试包流程。

## 计量契约

- 每 Key 独立配置每日／每月硬额度，0 表示关闭；原有软预算仍仅提醒。新字段默认 0，旧配置兼容。
- 仅对硬额度启用期间的业务请求独立计量，不追溯历史统计；关闭再开启不清空已有额度账。计数接口与模型发现不扣额度。
- 输入与输出合计，不再次叠加缓存、推理子计数。归属请求获得额度预留时的 UTC 日／月；跨日完成仍结算原周期。
- 生成请求在硬额度启用时先归一化输出上限，再使用同一目标引擎的精确输入计数。兼容省略、null、-1、-2、常见输出参数别名、整数字符串与单元素 prompt 数组；缺省使用每 Key 可配置的 32768 Token，上下文不足时仅缩小自动补齐值。多个显式有限上限取较小值，移除覆盖参数并写入对应协议字段，预留与实际转发使用同一有效上限。多份生成和多 prompt 批次仍拒绝并提供具体 code/param；不能可靠预检时拒绝转发。
- 向量与重排序按引擎实际公布的上下文上限乘输入条数保守预留；批量按全部条目计算，不按返回的 top_n 计算。无法确认边界时拒绝，完整响应再释放多余预留。
- 使用独立 SQLite 额度账，事务内同时检查日、月已结算量与未结算占用。成功提交预留才转发；存储不可用时关闭放行。
- 完整成功响应按上游归一化用量幂等结算。取消、断流、超时、失败或未知／部分用量按至少原预留额保守占用；本地未转发的请求释放预留。实际报告超预留时记入全部实际量。
- 崩溃遗留和结算写入失败不自动退款；页面分别显示已结算与待结算／保守占用。管理员可调整额度，不能通过清除使用统计清空额度账。不提供把未知量一键当作零的功能。
- 额度账不保存密钥、提示词或输出正文。它用于本地容量／用量约束，不是正式计费凭据。不能约束绕过路由直接访问实例的调用。

## 验收

- 原子并发预留、日月双重限制、不同 Key 隔离、精确临界值、幂等结算、跨 UTC 日月、数据库锁／写入失败、重启与未知用量。
- HTTP 层验证拒绝发生在推理转发前，兼容各协议错误格式；默认关闭时保持原行为。旧后台必须通过新能力标记升级后才可启用本轮配置。
- 双语配置与统计页面覆盖额度保存、已结算／占用展示；清除统计后额度保持。
- 隔离数据目录和端口，使用实际生成、向量与重排序 GGUF 核对响应、使用统计和额度账，不修改日常实例配置。
- 运行相关 Rust、浏览器、发布检查、生产构建、后台 IPC 测试，随后提交 PR 并生成 Windows CI 测试程序。

## Octop 与缺省输出上限兼容修复（2026-09-16）

Octop / LangChain 默认请求只发送 model、messages、stream，旧硬额度校验因此返回 token_quota_invalid_limit；软预算和硬额度关闭时没有这一限制。修复覆盖四种生成接口，统一常见输出别名与单份生成参数，并提供每 Key 缺省输出上限。明确的零上限原样转发；真实 b10976 引擎仍报告一次采样，故至少预留 1 个输出 Token，完成后按实际报告结算。默认值根据精确输入计数和剩余上下文收缩，明确设置的有限上限仍按原值执行上下文检查。

- 13 类请求形态的隔离 HTTP 回归：Octop 缺省、null、无限量值、显式零、数字字符串、别名冲突、单元素 prompt、四种接口；同时验证额度临界值、错误 code/param、计数不可用、多份生成拒绝、软预算单独开启时原样转发，以及工具／图片字段保留。
- 真实 Qwen3.5-2B 与 Qwen3-Embedding-0.6B：24 次成功调用、30 条统计记录对账通过。包括四种生成接口普通／流式各两组、别名、零上限、双 Key 并发与向量格式。没有请求流式 usage 的客户端仍保持原有响应，路由账本正常结算。
- 完整 Rust 502 通过、2 个按需测试忽略；88 项浏览器、生产构建、发布检查、Clippy、后台生命周期与新增 HTTP 回归通过。缺省上限保存／重载以及深浅主题、窄窗口已核验。
- 新后台能力为 router_usage_v5，避免安装修复后继续复用旧额度实现。六项必需 CI 和新 Windows 测试包在 PR #123 跟踪；继续等待用户验收后合并。
