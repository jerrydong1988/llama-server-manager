# 功能审计修复与交叉验证

审计基线：`codex/agent-management-exploration` 的 `1ca1d455`。以下记录探索分支的修复与验证；后续集成状态以 PR 和测试包 `BUILD.json` 为准，正式版本另行发布。

## 修复映射

| 审计项 | 实现与验证重点 |
| --- | --- |
| F01 引用中的实例被 GUI 删除 | GUI 与 CLI/MCP 共用后端删除事务，校验配置版本、路由/default 引用和运行状态；普通 GUI 保存也校验删除的实例引用。禁用路由同样保留引用保护。 |
| F02 删除提交失败留下副作用 | 后端提交成功才移除 GUI 实例并清理检查点和日志。提交失败时保留原实例及数据；后续清理失败作为可见告警，未清理文件保留。 |
| F03 下载事件早于回执 | 入队前登记 run/version，提交失败按身份回滚；单项/全部恢复后合并后端快照，过滤旧 run 事件及已完成排队记录。 |
| F04 配置持久层与内存不一致 | GUI 保存持有配置写锁直到内存发布结束；实例读取的参数和 revision 来自同一个持久配置快照。 |
| F05 路由启停后保存冲突 | 启停成功后校验并刷新配置版本；发现并发外部修改时保留草稿并报告冲突。浏览器 mock 实施相同版本检查。 |
| F06 保存回执覆盖新编辑 | 仅在草稿仍等于提交快照时应用保存回执；保存期间的新编辑继续保留。 |
| F07 扫描发布 | **更正原审计结论**：完整扫描原有锁已经覆盖扫描、提交和发布，两次扫描覆盖的截取复现不成立。实际修复启动缓存恢复：与模型及引擎扫描共用锁，防止旧缓存覆盖已完成扫描。 |
| F08 RPC 文件名 | 本地发现/启动支持 `ggml-rpc-server` 和 `rpc-server`，Windows 加 `.exe`，新名称优先；目录布局单测和实际 Worker 启停验证。 |
| D01 全局写锁阻塞控制 | 按实例/领域调度，网络准备不占提交锁，配置仍以 revision 校验。增加 queued 任务取消及取消终态；running 事务不强行中断。 |

## 自动化回归入口

- `npm run check:release`：完整前端、浏览器、功能脚本和发布门禁。
- `npm run build`：生产前端及测试 mock 隔离。
- `cargo test --manifest-path src-tauri/Cargo.toml --locked`：后端功能回归。
- `npm run test:management`：真实宿主、CLI、stdio MCP 与合成引擎；覆盖慢探测期间实例停止、排队修改取消、新名称 RPC 和引用保护。通过 `LSM_TEST_PROFILE=release` 选择测试构建。
- `node scripts/test-functional-state.cjs`：下载事件提前到达、恢复快照、旧 run 过滤、入队失败回滚。
- `browser-tests/functional-audit.spec.ts`：路由启停/保存、保存期间编辑、实例引用/写入/版本失败及成功后的清理次序。
- `npm run test:runtime-service`：使用当前源码的 debug 构建测试后台恢复和路由配额协议。其模拟登录注册标记仅在 debug 中生效；release 的后台恢复另用真实注册和真实模型验证。

## 实机交叉测试

在独立测试目录中使用同一构建的 GUI、CLI 与新建 stdio MCP 会话。测试前停止负载，备份程序和数据；保留既有模型/引擎文件。

覆盖模型刷新与引用保护、引擎探测、实例创建与启停、参数双向读写、下载完整生命周期、路由与用量对账、真实检查点及后台恢复。详细运行证据、实际结果和尚未验证的平台写入独立部署的 `validation/functional-audit-20261019/`；本文件不将旧轮次实测结果当作本轮已通过结果。

新增 `tasks_cancel` 由全新 MCP stdio 会话枚举。已经启动的旧 MCP 进程可以继续使用旧目录中的操作；完整新工具目录需要重连到新 `lsm`。取消任务直接返回终态，不使用 `mutate` 的 task_id 等待封装。
