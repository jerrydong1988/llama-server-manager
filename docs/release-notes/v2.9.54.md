# v2.9.54 — 修复退出后自动唤醒与稳定版参数适配

本版本修复 MCP 连接导致桌面程序退出后重新出现在托盘的问题，更新 llama.cpp v0.8.0 参数兼容性，并增加受控的本地检查点验证与准入能力。

## 桌面退出与 CLI／MCP

- MCP 初始化、工具枚举、重连和工具调用均不会自动启动或重启管理宿主；退出后保持停止，连接失败时返回明确提示。
- 管理操作需先打开桌面应用，或由用户显式执行 `lsm service start`；启动宿主后，已有 MCP 会话可继续使用，无需重连。
- 管理服务启动时不创建窗口或托盘图标；主动打开界面或执行 `lsm service show --wait` 后恢复桌面界面与托盘，重复显示不会重复创建。
- 保留 CLI／MCP 的权限检查、共享任务和管理操作；已授权的独立后台运行时继续按原有策略管理工作负载。

## llama.cpp v0.8.0 兼容性

- 稳定版参数基线更新至 v0.8.0，共跟踪 261 个参数条目，并保留对开发分支的独立检查。
- 更新保留推理轨迹的说明：继承时不传开关，v0.8.0 遵循聊天模板默认值；显式开启或关闭仍需模板支持。
- 上游多模型路由可通过自定义参数使用 `--models-memory-margin`；实验性 `--connect` 与 `--connect-code` 限于手动命令模式，命令预览和管理回执会隐藏显式连接码。
- 补齐 LFM3 混合架构的检查点保护并验证 DeepSeek 4.1 分类；旧检查点资格记录需按新策略重新评估。

## 检查点验证与准入

- 增加已验证本地 b12000 Windows／ROCm 构建在限定模型、四槽配置及混合推测策略下的检查点验收范围；不代表所有 b12000 构建或模型均获支持。
- 增加隔离的本地检查点验证流程，以实际保存、跨进程恢复和缓存复用结果评估当前配置，支持通过界面和管理接口提交与查询验证任务。
- 验证证据绑定引擎、模型和运行配置，变更或证据失效时重新评估；恢复不完整时保持不可路由，不将部分成功当作完整恢复。
- 保留默认关闭及回退冷启动策略，未验证的架构、参数组合和后端仍受现有安全边界约束。

## 安装与升级

- 更新构建与静态检查工具链中的 minimatch，修复复杂 glob 预处理可能导致的资源耗尽问题，并增加调用方兼容性与有界输入回归检查。
- Windows x64 提供 EXE／MSI，macOS Apple Silicon 提供 DMG，Linux x64／ARM64 提供 DEB；AppImage 仍处于候选验证阶段。
- 升级沿用已有实例、模型与引擎目录、路由、API Key、任务和用量数据，不需要重新创建配置。
- 已运行的旧 MCP 客户端需要重连以加载新版 CLI；新版仅连接已运行宿主，不会因客户端初始化而重新显示托盘。
