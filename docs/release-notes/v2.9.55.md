# v2.9.55 — 接入 Gufo 与完善统一 API 路由

本版本增加 Windows Gufo 实例管理，沿用现有模型、引擎与统一 API 工作流，并修复人工测试和发版前审计发现的路由、配置及生命周期边界问题。

## Gufo 实例管理

- 支持识别本地 Gufo 引擎，配置模型与推测解码，管理启停、加载状态、日志和监控；保留现有 llama.cpp 实例与检查点功能。
- Gufo 使用 Manager 数据目录下的独立实例缓存和运行环境，不改写已有 Gufo-GUI 配置与缓存；启动就绪检查同时核对引擎状态和模型身份。
- 已验证本机 Gufo 0.28.1 的 Qwen3.8-Flash-Next + MTP、Qwen3.8-27B Q8 + DFlash2 两套模型；这不代表所有平台、Gufo 构建和模型组合均已验证。

## 统一 API 与诊断

- 接入原生 Chat Completions、Responses、Anthropic Messages 及其计数能力；按实际引擎能力执行上下文预检和用量管理。
- 区分容量已满、目标不可用、缺少模型、未知模型和接口不匹配；容量满时继续立即返回 503，并提供可识别错误码与 Retry-After 提示，不引入目标排队。
- 修复容量拒绝等本地错误漏计、混合请求头导致协议误判和响应头冲突；补齐 404／405 诊断与指标说明。
- Chat 生成请求在转发前检查工具调用与结果是否配对；支持并行结果乱序及工具失败、取消结果，不修改工具内容。其他原生协议和计数接口保持各自契约。
- 思考预算、输出截断和 stop 行为保持引擎语义；客户端应检查完成状态，固定的最小 Token 预算不能保证工具调用完整结束。

## 发版前审计修复

- 跨引擎切换保留实例的内联 API Key；Gufo 保存失败时不覆盖随后发生的配置更新，并保留用户草稿。
- 修复目标停止、清理并重建后，旧请求错误释放新目标槽位的问题。
- 修复重叠引擎目录在缓存复用和重新扫描混合时出现重复条目的问题。
- 修复 Unix 缓存写入锁可能被继承描述符延长、导致立即重启被误判为占用的问题。

## 安装与升级

- Windows x64 提供 EXE／MSI，macOS Apple Silicon 提供 DMG，Linux x64／ARM64 提供 DEB；Gufo 新增集成目前限 Windows，其他平台继续使用 llama.cpp。
- 升级沿用现有实例、目录、路由、API Key、任务和用量数据；不会自动迁移现有实例到 Gufo，也不包含模型文件或自动替换已有引擎。
- 保留仅连接已运行宿主的 MCP 生命周期；安装升级与用户现有服务的启停策略保持一致。
