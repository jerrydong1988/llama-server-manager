# v2.9.49 — 交互引导改进与安全性能修复

本版本将首次运行引导串联为连续流程，修复参数页面引导与保存按钮互相遮挡的问题，并集中加强下载文件保护、后台启动校验和 API 路由资源限制，改善请求记录查询与后台监测效率。

## 交互引导与界面

- 首次运行引导贯穿模型、引擎、实例、参数、启动和连接验证，保留步骤进度，结合实际配置与运行状态判断是否可以继续。
- 参数页面引导与底部保存工具栏协调占位，展开、收起和滚动时保持主要操作可见，兼顾中英文、深浅主题及窄窗口布局。
- 保存失败、连接失败和离开当前步骤时提供更明确的恢复路径，减少重复操作与流程中断。
- 修复删除实例后迟到的状态、日志和监测事件重新填入旧数据的问题。

## 安全与稳定性

- 下载任务使用原生文件身份记录与固定目录句柄，拒绝覆盖不属于任务的文件；实例仍引用的模型不能被下载清理或覆盖。
- 收紧临时文件清理范围，避免将模型目录中的同名文件误判为程序临时文件；路径授权变更及时生效，损坏的授权记录不会被自动放宽。
- Windows 后台通信验证管道服务端的用户和程序身份；后台启动及恢复校验引擎可执行文件的授权路径和内容摘要。
- API Key 显式空权限不再获得默认推理权限，请求上传期间撤销或修改密钥后，在转发前重新校验权限。
- 为请求上传和下游响应交付设置时限与内存边界，限制等待队列，并按实例共享容量，减少慢连接或单个密钥占满资源的影响。
- 启动命令与历史遥测记录中的凭据进行脱敏，SSH 操作限制等待时间与输出量；补入依赖安全修复及对应回归验证。

## 性能与兼容性

- 请求记录按实际筛选条件生成查询，使用请求 ID 等索引；数据库普通读取避免重复执行建表和迁移，减少写锁竞争。
- 后台健康采集缩短生命周期锁占用，性能查询对过大结果集给出缩小范围提示，避免无界读取。
- 更新 llama.cpp v0.5.0 参数基线，继续跟踪 255 个参数条目；本次上游变化未改变这些参数的数量和默认值。实例主机字段仍使用单个监听地址。
- 发布流程先生成草稿，待全部平台安装包和更新清单上传成功后再公开版本并同步官网，避免展示尚未完成的下载入口。

## 安装与升级

- Windows x64 提供 EXE／MSI；macOS Apple Silicon 提供 DMG，最低要求 macOS 13；Linux x64／ARM64 提供 DEB。
- Windows 与 macOS 的 v2.9.36 及以后版本支持应用内更新；更早版本及 Linux DEB 需要手动安装。Linux AppImage 和 Linux 应用内更新继续暂停。
- 未配置商业证书时，Windows 安装包标记为 unsigned，macOS 使用 ad-hoc 签名；应用内更新仍执行独立的 Tauri 签名验证。
- 建议在请求空闲、下载任务完成后升级。现有实例、路由、API Key 和额度配置继续沿用。
- 旧版保存的后台启动记录缺少引擎内容摘要时，自动恢复会被安全校验拦截；请在升级后从应用中手动启动相应实例一次，以更新启动记录。更换引擎文件后也需要重新确认启动。
- 旧版下载临时文件缺少原生所有权记录时，不会自动接管或删除。若续传提示文件不属于任务，请保留需要的文件，确认后将冲突文件移出下载目录，再重新创建下载任务。
