# Agent 管理接口探索

分支：`codex/agent-management-exploration`。起点：`82abee4`，版本 2.9.52。
本分支用于人工验收，不自动合并 master，不创建正式版本。

## 目标与交付边界

让桌面界面、命令行和 MCP 操作同一份模型、引擎、下载、实例、集群及路由状态。
所有操作复用 Rust 的校验和执行路径；CLI 和 MCP 不自行修改 instances.json，不执行拼接的 shell 命令。
探索版首先提供本机、当前操作系统账户内的管理。远程网络管理不开放。

管理宿主复用桌面应用的 AppState 和现有命令实现，通过私有本地 IPC 接受请求。
CLI 可启动隐藏的管理宿主；关闭或隐藏窗口不会终止管理任务。显式退出应用会停止管理宿主，
独立推理运行时继续遵循现有后台策略。客户端退出不取消已提交任务。
Linux 的管理宿主仍需要桌面会话；真正无 DISPLAY 的 Linux daemon 需要将 Tauri AppHandle
进一步抽象为事件与状态服务，属于明确的后续平台边界，不能宣称本探索版已经支持。

## 架构与职责

1. **管理契约**：版本化操作目录、输入 JSON Schema、输出信封、错误码、只读/修改/删除标记。
2. **本地传输**：Windows 命名管道、Unix socket；独立于推理控制令牌；账户/端点校验、帧大小和超时限制。
3. **管理宿主**：认证、参数校验、序列化配置修改、任务登记、执行、审计及 UI 变更通知。
4. **领域适配**：调用现有扫描、下载、能力探测、启动校验、运行时、集群及路由实现。
5. **CLI**：独立控制台入口，帮助、操作发现、JSON 参数文件、JSON 输出、退出码、任务等待、服务启动。
6. **MCP**：stdio 工具、结构化结果、能力发现；默认只读，按启动配置开放修改、删除、远程集群操作。
7. **GUI 同步**：配置版本与变更通知；外部修改不能被陈旧前端快照覆盖。界面保持现有操作方式。

## 一致性和执行语义

- 修改操作使用宿主内统一锁；按对象修改和 GUI 快照保存共享配置边界。
- 基于配置内容的 revision 用于陈旧快照检测；冲突不重试覆盖，调用方先读取新配置。
- 请求信封返回 id；修改任务返回 task_id，支持后续查询和等待。
- 显式幂等键用于副作用请求；相同键不同参数拒绝；持久化任务记录，崩溃后标记 interrupted，不能伪报成功。
- 成功返回是操作已完成/已入队的具体含义；启动进程成功与健康 ready 分开。
- 任务保留 200 条，摘要查询返回 100 条；单条结果限 128 KiB。幂等窗口与保留窗口一致，输入参数不落任务日志，输出敏感字段脱敏。
- 删除预览给出文件范围和引用；执行再次校验，不依赖过期预览。
- 配置更改发送事件，前端重新加载；前端保存携带原版本，防止 GUI 旧快照覆盖外部修改。

## 安全与兼容

仅当前账户本机连接，管理凭据和推理 API Key 隔离。MCP 权限在适配层执行，工具目录仅展示
允许的操作。CLI 作为账户所有者管理入口具备完整权限。参数为结构化数据，不能把任意命令
执行器作为管理工具。日志、路由、实例配置输出脱敏；敏感字段更新采用明确 patch。

MCP 使用标准 stdio JSON-RPC，stdout 仅输出协议，诊断写 stderr；固定并说明支持的协议版本。
不要求客户端支持可选 Tasks 扩展，任务查询作为普通工具提供。CLI 支持无 MCP 的 Harness。
服务端和客户端版本不兼容时明确拒绝，不能将旧二进制静默当作新服务。

## 验证计划

1. 契约：所有操作可发现、输入 schema 和实现一致、未知字段拒绝、错误可机器判断、敏感值脱敏。
2. 传输：认证失败、错误版本、超大/不完整帧、超时、连接断开、多客户端、重复请求。
3. 引擎：新增目录、刷新、重命名、默认引擎、探测、替换二进制后缓存失效、被引用/运行中删除保护、目录移除不删文件。
4. 实例：创建/修改/克隆/删除、缺失模型/引擎、端口冲突、手动端口、参数兼容、启停幂等、健康状态。
5. 一致性：GUI 与 CLI 同时修改、两个 CLI 同时更新、保存过程失败、宿主重启、旧版本客户端。
6. 下载：排队/进度/暂停/恢复/取消/重试/限速、客户端退出、宿主重启、部分文件保护。
7. 集群与路由：节点校验、SSH 配置错误、路由探测、热变更限制、密钥脱敏和保留。
8. MCP：initialize、tools/list、tools/call、只读权限、结构化错误、长任务查询、EOF 退出。
9. 全量门禁：check:release、生产构建、Rust 测试与严格 Clippy、运行时回归、跨平台 CI。
10. 人工交付：分支提交、测试包、SHA256、CLI/MCP 接入示例、逐项验收清单和实际验证范围。

## 回退

探索版使用明确指定的数据目录测试。用户现有模型和引擎文件不搬移。
配置格式新增字段保持向后兼容；新管理数据存放于独立 management 目录。
停止探索版宿主后可启动 master 测试包；不得同时运行两个版本写同一数据目录。

## 后续演进条件

1. **真正无图形依赖的宿主**：把 AppHandle 中的事件、路径选择和授权对话框抽象为服务接口，再将领域逻辑迁移到共享库；CLI/MCP 契约保持稳定，逐个迁移，避免双写配置。
2. **引擎安装器**：平台/后端/架构清单、可信下载地址及校验和、归档路径保护、暂存探测、原子安装、版本回退、使用中文件锁。应形成独立领域，不能直接开放任意 shell 安装命令。
3. **远程管理**：另行设计认证、权限、TLS、请求审计和远程目录语义；本机 IPC 不直接绑定公网。
4. **更大规模任务**：按资源并发、分页、任务取消/进度、长期幂等账本。当前串行写队列优先保证正确性；取消下载和停止实例已有领域操作，不能宣称能取消任意管理任务。
5. **验收后集成**：探索分支保留；收集各平台桌面、真实远端集群、长下载反馈后再决定生产集成和版本化。当前不合并、不打标签、不发布正式版本。
