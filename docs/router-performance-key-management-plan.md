# 路由性能与 Key 管理合并迭代

日期：2026-09-15。基于用户已验收并合并的 PR #120（`dd0eae9`），在 `codex/router-performance-key-management` 实施第三、第四步，统一提交 PR 与 CI 测试包。

## 交付范围

1. 性能统计：排队、首个有效输出、总耗时 P50/P95；小时趋势、慢请求检索；按 Key、模型、实例分析。
2. 实时容量：全局与 Key 的正在处理／排队数量，以及模型、实例占用；与历史统计明确区分。
3. 用量管理：每 Key 的每日／每月 Token 软预算与页面提醒，固定使用 UTC 周期，沿用现有真实报告计数。
4. 调度管理：每 Key 并发上限、可选的按 Key 轮转的全局入场队列，沿用现有 RPM。目标实例仍单独检查容量，不把全局队列许可当作引擎空闲槽位。
5. 首页摘要、基线提示和采集开销验证；旧配置、旧统计及独立后台运行时兼容。

## 统计口径

- 使用稀疏、可合并的耗时直方图计算分位数，不平均各时段的 P95。展示近似分位数及样本数，并说明精度。
- 总耗时与首个有效输出分析成功的业务请求；首个有效输出仅在实际观察到流式有效输出时采样，不将非流式响应或未输出记为零。
- 排队样本只纳入实际经过入场队列的业务请求，包含等待超时；鉴权失败与计数接口不混入业务性能分布。
- 新性能分布从本版本开始记录；旧请求明细仍可用于慢请求检索，不从旧耗时总和伪造分布。
- 独立保存每日／每小时性能聚合，与基础统计使用同一写入事务和请求去重边界。日聚合保留 365 天，小时聚合保留 30 天，清除统计时同步清除。
- 与前 7 个完整 UTC 日比较时，必须有足够样本；样本不足显示积累中，不触发性能异常提示。

## 管理边界

- 软预算只提醒，不拒绝请求；输入和输出仅相加已报告部分，不再次叠加缓存或推理子计数。未知、部分及可能的记录缺口继续提示。
- 预算不随页面历史日期或模型筛选改变，始终显示当前 UTC 日／月的对应 Key 业务用量。
- Key 并发额度覆盖请求等待正文、转发和响应流生命周期；释放、取消、超时以及热更新不能泄漏许可。零表示沿用全局上限。
- 公平队列在正文缓冲前调度，按 Key 轮转并保持同一 Key 内顺序，设有等待数量上限；取消的队列项必须及时移除。
- 公平调度与软预算由配置显式启用。尊重全局、Key、路由及已知实例槽位约束，不自动扩大用户现有并发配置。
- 强制 Token 额度、预扣／结算及自动扩容不纳入本轮。

## 验收

- 分位数合并、已知零／未知、旧记录、统计事务重试、时间边界与清除保留策略。
- 多 Key 排队公平性、并发上限、热更新、取消和超时、流式响应结束后释放；请求正文仍在获得许可后读取。
- 日／月预算边界、超预算继续转发、Key 改名保持身份、部分用量和采集缺口提示。
- 浏览器筛选、小时趋势、慢请求检索、管理配置往返、首页摘要、深浅色与窄窗口。
- 记录采集及聚合开销；运行适用回归、生产构建、独立后台服务验证，以及全部必需 CI。提供同一提交的 Windows 测试包，等待用户验收。

## 实现与本地验证

- 性能采用约 6.25% 向上量化的可合并直方图，P50/P95 按合并后的样本分布计算。历史数据仍可查看明细，但没有分布时显示缺失。
- 基线为筛选开始日期前 7 个完整 UTC 日，各至少 20 个样本，当前 P95 超过基线 2 倍才提示。预算达到 80%／100% 时在页面提示；不发送通知，也不自动拒绝请求。
- 公平队列与每 Key 并发覆盖正文读取到响应结束，队列上限 4096；目标实例容量单独判断，已知总槽位约束代理正在处理的请求。外部绕过路由的直接调用无法由本队列调度；没有槽位信息时仍遵守配置上限。
- 常规 Rust 测试 485 项通过，2 项按需测试默认忽略；浏览器全量 83 项通过。事务回滚／重试不重复计入性能分布；未知首个输出与真实零等待保持区分。
- llama.cpp b10976，Qwen3.5-2B-Q4_K_M 与 Qwen3-Embedding-0.6B-f16，CPU、4 线程、2 槽位：Chat／Responses／Anthropic 普通与流式、双 Key 并发、单条与批量向量共 10 次成功请求逐条对账一致，另 1 次取消正确释放许可。性能样本：总耗时 10、队列 11、首个有效输出 3。1 Token 软预算没有阻断后续请求；独立服务并发热更新生效。
- 调试构建、WAL 本地数据库、每批 100 条、10 个 Key，共 5000 条事件含原统计及日／小时分布落库耗时 765.8 ms，约 153.2 µs／条。此为本地采集吞吐观察，不能代表其它磁盘或生产推理性能；写入在后台线程批处理，不同步阻塞响应流。
- 真实模型测试可通过 Node.js 24 执行 `node scripts/test-router-real-models.cjs --engine <llama-server路径> --generation <生成GGUF路径> --embedding <向量GGUF路径> --report <结果JSON路径>`，先构建当前调试版。测试使用隔离临时目录及 CPU 小模型，不修改用户配置。基准通过 `cargo test --manifest-path src-tauri/Cargo.toml usage_capture_benchmark -- --ignored --nocapture` 按需运行。

CI 和用户验收分别记录在本轮 PR 中；强制 Token 额度仍待后续设计。
